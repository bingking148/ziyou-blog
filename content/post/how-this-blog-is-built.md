你现在看到的这个网站，没有租过一台服务器。

它跑在 Cloudflare 的免费额度上。我更新文章的完整流程是：打开编辑器写一个 Markdown 文件，git push，指的是把文件传到 GitHub 上的代码仓库，可以理解成点了一次上传。过两三分钟全网可见，没有登录服务器敲命令的环节，也没有每月要交的托管费。

这篇文章把这个站的架构从头到尾盘一遍：每一层用了什么，哪些免费哪些收费，踩过什么坑。下一篇开始，我会把它拆成手把手的教程，你在完全不会写代码的前提下，也能搭出一个一样的。

## 先盘家底

整站的技术选型，一张表说完：

| 层 | 用了什么 | 花了多少钱 |
|---|---|---|
| 存稿和版本管理 | GitHub | 免费 |
| 站点框架 | Astro 5 | 开源免费 |
| 构建和托管 | Cloudflare Pages | 免费额度 |
| 评论后端 | Waline，部署在 Vercel | 免费额度 |
| 域名 | 阿里云注册的 ziyou814.top | 一年几十块 |
| DNS 解析 | Cloudflare | 免费 |

表里唯一要花钱的是域名，一年几十块，还是「.top」这种便宜后缀。要是连这个都不想花，Cloudflare 会送一个 xxx.pages.dev 的子域名，照样能用，只是地址不那么像自己的站。

## 为什么是静态站

整个方案省心的前提，是我选了静态博客这个形态：每篇文章就是一个 Markdown 文件，整站构建出来就是一堆 HTML。没有数据库，没有后端进程，没有需要打补丁的服务器。

能挂的东西少了，能坏的东西也少了。

框架选了 Astro，有三个实际的原因：

1. 文章就是仓库里的 .md 文件，配了一套「内容集合」机制：每篇文章头部的标题、日期、分类会按我定义的格式做校验，字段写错、日期格式不对，构建直接报错，精确到文件和行号。错误在上线前就被拦住，而不是上线后被读者发现。
2. 默认往页面里塞的 JavaScript 很少。博客大部分页面就是文字，构建出来的页面不背一堆运行时框架，打开快。
3. 常用功能都有现成方案：RSS、站点地图、站内搜索、数学公式、代码高亮，不用自己造。

第 1 点对我这种文章越写越多的人最值。格式约束这种事交给机器盯，比靠自觉强。

## push 之后发生了什么

这个站真正省时间的部分在这里。

我在 Cloudflare Pages 上把 GitHub 仓库连了进去，配了一条构建命令。之后每次 git push，它自动做四件事：拉代码、装依赖、跑构建、把产物分发到全球节点，我这边什么都不用点。

贴一段刚收到的真实构建日志：

```
Detected the following tools from environment: nodejs@22.23.4
Executing user command: cd astro && npm ci && npm run build
```

第一行是构建环境自动识别出了 Node 22，第二行就是我配的那条命令：进入站点目录，按锁定文件干净地装一遍依赖，然后构建全站。这次构建 90 个页面，用时 24 秒，加上排队和分发，从 push 到线上两三分钟。

顺带说个写这篇文章当天刚踩的坑。我调整构建配置，命令在错误的目录里执行，`npm ci` 找不到依赖清单，直接报错：

```
npm error The 'npm ci' command can only install with an
existing package-lock.json
```

看到报错我第一反应不是慌，是安心：构建失败挡在了部署之前，线上还是上一个正常版本，坏不掉。修好配置点重试，一次通过。静态站这种「坏了也只是不更新」的特性，是我敢随便折腾的底气。

还有回滚。每次部署在 Cloudflare 后台都有记录，哪次改坏了，找到上一个正常版本点一下回滚，几十秒恢复，等于系统自带后悔药。

## 评论和阅读数

评论用的 Waline。这类系统需要一个常驻的后端接口，我把它部署在 Vercel 的免费额度上，评论数据存在自己配置的存储里，不托管在任何第三方评论平台上。

有个细节直接影响架构：评论是挂在文章地址下面的，地址一变，旧评论就成了孤儿。所以这个站的 URL 规则从第一天起就定死，每篇文章永远是 /post/slug/ 的形式，结尾带斜杠。以后就算换框架、换托管商，只要地址规则不变，评论和阅读数就都还在。

阅读数用的不蒜子，同样按地址计数。

## 国内访问这件事

静态站要面对一个现实问题：第三方资源。

很多博客的字体、图标、公式渲染脚本都从公共 CDN 拉。这在国内是隐患，我踩过一次：有段时间文章里的数学公式加载不出来，页面上全是乱码符号，查下来是那个公共 CDN 不可达。

之后我定了条规矩：所有第三方 JS、CSS、字体，全部下载下来放进仓库，构建时跟着站点一起发布。浏览器从头到尾只访问我自己的域名，不向任何公共 CDN 发请求。代价是仓库大了几 MB，换来的是任何地方打开这个站，渲染结果都一样。

至于 Cloudflare 本身在国内的速度，说实话看线路，时快时慢。但这个站页面轻、资源全在本地，日常打开没有明显问题。个人博客的流量规模，够用。

## 花了多少钱

最后算账：

| 项目 | 费用 |
|---|---|
| 域名（一年） | 几十块 |
| GitHub 托管 | 0 |
| Cloudflare Pages 构建和流量 | 0 |
| Vercel 评论后端 | 0 |

Cloudflare 免费额度有多宽裕，给个体感：最近五天这个站部署了八次，页面九十多个，文章二十来篇，额度连零头都没碰到。个人博客的量级，免费额度就是为这个规模准备的。

域名这笔钱严格说和建站方式无关，不管用什么方案，网址本身都要续费；真想一分钱不花，就用上面说的免费子域名。

## 下一篇

这套东西拆开看，每一步都不难，难的是第一次没人带着走：注册哪个账号、仓库怎么建、构建命令填什么、域名解析怎么指、评论怎么接，步步都有先后依赖。

所以从下一篇开始写教程，从打开电脑那一刻讲起：注册 GitHub、放进第一篇 Markdown、连上 Cloudflare Pages，十分钟后看到自己的站，然后绑域名、加评论。全程不需要写代码，会打字就行。

接下来第一步只是注册个 GitHub 账号，5 分钟的事。哪一步容易卡，卡了欢迎在评论区喊我，我按提问频率调整后面几篇的详略。
