上一篇的 [第 11 篇](/post/python-file-operations/) 让程序学会了「记住事」，文件这块拼图补完了。这一篇回到函数——第 6 篇和第 7 篇把你练成了函数的重度用户，但有两个别扭的地方一直没解决：

1. **函数调用完，里面的变量就销毁了**。有时你就是想让一个变量跟着函数一起活下去——比如一个只属于某个函数的计数器、一组模型参数。return 只能把**值**交出去，变量本身留不住；
2. **同一个功能想加给一堆函数**。十个函数都要加「先检查登录」、都要打印执行日志，难道把同样的代码复制十遍？以后改一处就得改十处。

这两个问题的答案是同一个东西：**闭包**——以及它在真实项目里的化身，**装饰器**。这是 Python 最优雅的特性，也是这个系列最后一块拼图。

## 1. 函数的「失忆症」

先看清问题本身。函数里的局部变量，寿命和函数调用一样长：

```python
def outer():
    x = 10
    print(f'x = {x}')

outer()          # x = 10
print(f'x = {x}')   # NameError: name 'x' is not defined
```

`outer()` 调用一结束，函数内部的所有变量就被销毁了，外面想拿也拿不到。第 6 篇讲过：这是**局部变量**的本分——隔离，防污染。

想留住变量，第 6 篇给的方案是 return：

```python
def func():
    number = 10
    return number

num = func()     # 把值交出去
print(num)       # 10
print(num + 1)   # 11
print(num + 2)   # 12
```

但注意：交出去的只是**值**，`func` 里的 `number` 本体照样销毁。`num` 和 `number` 是两个变量，改 `num` 影响不到函数内部。

有没有办法让变量本体跟着函数一起活下来？先看一个前置知识。

## 2. 嵌套函数：函数里还能定义函数

Python 里函数定义是可以嵌套的——函数里面再定义一个函数：

```python
def outer():
    x = 10

    def inner():                    # 内部函数
        print(f'我看到了 x = {x}')   # 内部函数能读到外部函数的变量

    inner()                         # 在外部函数里调用它

outer()   # 我看到了 x = 10
```

`inner` 能直接读 `outer` 的变量 `x`——这和「函数能读全局变量」是同一个查找规则：自己没有，就往外一层找。

重点在下一步：**函数也是对象**（第 7 篇说过，函数能当参数传），所以——**函数也能当返回值**。把 `inner` 返回出去，会怎样？

## 3. 闭包：把变量关进函数里

```python
def fn_outer(number1: int):
    # 外部函数的参数

    def fn_inner(number2: int):
        # 内部函数使用了外部函数的变量 number1
        sum_result = number1 + number2
        print(f'求和结果：{sum_result}')

    return fn_inner     # 返回内部函数（注意：不带括号，返回的是函数本身）
```

```python
f1 = fn_outer(10)
print(f'外部函数返回值类型：{type(f1)}')   # <class 'function'>
print(f1)                                # <function fn_outer.<locals>.fn_inner at 0x...>

f1(1)      # 求和结果：11
f1(10)     # 求和结果：20
f1(100)    # 求和结果：110
```

盯着这段代码看三件事：

1. `fn_outer(10)` 执行完，返回的是 `fn_inner` 这个**函数**——`type` 显示 `function`；
2. `f1(1)` 调用的是内部函数，可它算出 `10 + 1`——**外部函数早就执行完了，`number1 = 10` 居然还活着**，被内部函数记住了；
3. 再造一个：`f2 = fn_outer(50)`，那 `f2` 记住的是 50，和 `f1` 的 10 **互不干扰**——每次调用外部函数，都开一个独立的「记忆空间」。

这就是**闭包（Closure）**。一句话：**闭包 = 函数 + 被它记住的变量**。

判定闭包的口诀是「三有」：

> 1. **有嵌套**——外部函数里嵌套定义内部函数；
> 2. **有引用**——内部函数使用了外部函数的变量（含参数）；
> 3. **有返回**——外部函数返回内部函数。

三条缺一不可。少第三条（不返回），内部函数出不了外部函数的门；少第二条（不引用外部变量），返回的只是普通嵌套函数，没有「记忆」。

写法上还有个顺手的变体——链式调用，`fn_outer(100)(100)` 直接返回的函数上再传参，两步并作一步，结果是 200。读别人代码时见到这种连着两个括号的，就是在调闭包。

## 4. nonlocal：闭包里改外部变量

闭包里的内部函数默认只能**读**外部变量，想**改**，得声明一下：

```python
def fn_outer():
    a = 100

    def fn_inner():
        nonlocal a       # 声明：这里的 a 是外部函数的那个 a
        a = a + 1
        print(f'a = {a}')

    return fn_inner

f1 = fn_outer()
f1()    # a = 101
f1()    # a = 102
f1()    # a = 103
```

`nonlocal` 和第 6 篇的 `global` 是一对：

| 关键字 | 声明的是谁的变量 | 用在哪 |
|---|---|---|
| `global` | 全局变量 | 函数里改全局变量 |
| `nonlocal` | **外部函数**的变量 | 嵌套函数里改外层函数的变量 |

不加 `nonlocal` 直接 `a = a + 1` 会怎样？Python 会认为你在内部函数里**新建**了一个局部变量 `a`，但赋值右边又要先读它——自己读自己还没建好的变量，直接 `UnboundLocalError`。和第 6 篇 `global` 那个坑同根同源。

`f1()` 每调一次加一，101、102、103——这个被闭包记住的 `a` 是**活的**，会一直变化。这就是闭包版计数器：状态藏在函数里，全局命名空间干干净净。还记得第 6 篇说 `global` 能不用就不用吗？闭包就是更体面的替代品之一。

## 5. 闭包实战：线性回归的雏形

来一个 AI 味的案例。机器学习最先接触的算法是**线性回归**：`y = k * x + b`。训练过程就是不断调整 `k` 和 `b`；而每调整一轮，都要用固定的 k、b 去算一遍所有样本的 y。

```python
def linear(k: float, b: float):
    # 外部函数接收 k、b——相当于模型的参数

    def inner(x: float) -> float:
        # 内部函数使用外部的 k 和 b
        return k * x + b

    return inner


x_list = [100, 121, 124, 135, 150, 97]

f1 = linear(k=10, b=20)
y1_list = [f1(x_item) for x_item in x_list]
print(y1_list)    # [1020, 1230, 1260, 1370, 1520, 990]

f2 = linear(k=8.5, b=11.3)
y2_list = [f2(x_item) for x_item in x_list]
print(y2_list)
```

这个案例值得品：`linear(k=10, b=20)` 造出了一个「专用模型」`f1`——它记住了自己的 k 和 b，之后反复调用只管代入 x。`f2` 是另一组参数下的另一个模型，两个模型各记各的参数。

**闭包记住的变量，本质上就是模型的参数。** 以后你调 `model.eval()` 时传入的权重，在概念上就是被某个函数记住的 `k` 和 `b`——只是规模大了几亿倍。

## 6. 装饰器：闭包的杀手级应用

闭包会写了，看它在真实项目里的头号用法。

需求：电商程序里，下单、支付、发表评论——每个操作前都得**先检查登录**。原始写法：

```python
def comment():
    print('检查登录.....登录成功.......')    # 复制粘贴第一遍
    print('发表评论..................')

def payment():
    print('检查登录.....登录成功.......')    # 复制粘贴第二遍
    print('支付商品...................')
```

检查逻辑和业务逻辑搅在一起，十几个函数就要复制十几遍——第 6 篇说「一个函数只做一件事」，这就违反了。

换思路：写一个**接收函数、返回增强版函数**的闭包：

```python
# 装饰器：给原函数加上登录检查，不改动原函数一行代码
def check_login(fn):          # 外部函数：参数是被装饰的函数
    def fn_inner():           # 内部函数
        print('检查登录.....登录成功.......')   # 额外功能
        fn()                  # 调用原函数

    return fn_inner


def comment():
    print('发表评论..................')

def payment():
    print('支付商品...................')

# 用法一：传统写法——手动装饰
f1 = check_login(comment)
f1()    # 检查登录...登录成功...  发表评论...

f2 = check_login(payment)
f2()    # 检查登录...登录成功...  支付商品...
```

`check_login(comment)` 返回了一个「先检查登录、再评论」的新函数。原函数 `comment` 一行没动，检查逻辑只写了一遍，谁要就给谁套上——这就是**装饰器（Decorator）**：本质上依然是闭包，只是外部函数的参数从数字换成了**函数**。

再补一个语法糖。Python 觉得「手动装饰再赋值」太啰嗦，允许直接在函数定义上方写 `@装饰器名`：

```python
@check_login
def order():
    print('正在下单...................')

order()   # 检查登录...登录成功...  正在下单...
```

`@check_login` 这一行完全等价于 `order = check_login(order)`——定义完立刻自动装饰，之后照常调用原函数名。两种用法效果一样，**实际项目一律用 `@`**；理解原理时想想「手动版」就够了。

## 7. 有参有返回的装饰器

第 6 节的装饰器只能装饰「无参无返回」的函数。可真实的函数千姿百态——比如一整个计算器模块：

```python
from typing import Callable

def operator_decorator(func: Callable[[float, float], float]) -> Callable[[float, float], float]:
    # 外部函数：参数是函数，返回值也是函数

    def fn_inner(x: float, y: float) -> float:
        print('正在努力计算中................')   # 额外功能
        return func(x, y)                        # 调用原函数，返回它的结果

    return fn_inner


@operator_decorator
def plus_operator(num1: float, num2: float) -> float:
    return num1 + num2

@operator_decorator
def minus_operator(num1: float, num2: float) -> float:
    return num1 - num2

@operator_decorator
def divide_operator(num1: float, num2: float) -> float:
    return num1 / num2

@operator_decorator
def rest_operator(num1: float, num2: float) -> float:
    return num1 % num2


print(plus_operator(10, 20))    # 正在努力计算中...  30
print(minus_operator(10, 20))   # 正在努力计算中...  -10
print(divide_operator(10, 20))  # 正在努力计算中...  0.5
print(rest_operator(10, 20))    # 正在努力计算中...  10
```

和第 6 节比，只改了两处，但都是关键：

1. **`fn_inner(x, y)` 收下参数**——装饰后的函数被调用时，参数先到内部函数手里，内部函数转手 `func(x, y)` 传给原函数。原函数要什么参数，内部函数就收什么、传什么；
2. **`return func(x, y)` 把结果带回去**——原函数的返回值经内部函数原样返回。少写这个 `return`，所有被装饰的函数永远返回 `None`。

装饰器的完整心智模型一句话：**内部函数是原函数的「代理人」——参数由它转交，结果由它转达，额外功能插在中间。**

那行 `Callable[[float, float], float]` 类型注解也解释一下：`Callable` 表示「可调用对象（函数）」，方括号里 `[参数类型列表, 返回值类型]`——「接收两个 float、返回 float 的函数」。第 6 篇你只注解过普通参数，这里第一次注解「函数参数」，写法记住即可。

再看一遍这五个函数加、减、除、取余全挂同一个装饰器——「日志」「计时」「权限检查」「重试」这些横切功能，以后你全用这一招加。

## 8. 常见坑清单

1. **忘了 `return fn_inner`**——外部函数返回 `None`，`f1 = fn_outer(10)` 拿到的是 `None`，一调用就 `'NoneType' object is not callable`。三有口诀的第三有，忘得最多；
2. **返回时带了括号**——`return fn_inner()` 是「调用并返回结果」，`return fn_inner` 才是「返回函数本身」。写错的话，返回值立刻被执行一次，之后全是 `None`；
3. **以为闭包复制了变量**——闭包记住的是变量**本身**。`nonlocal` 改一次，所有引用它的地方都变了；多个内部函数共享同一份外部变量，不是各存一份；
4. **只读不改却加了 `nonlocal`**——只在内部函数里读外部变量，不需要 `nonlocal`；要**赋值**才需要。乱加不报错，但说明概念没理清；
5. **装饰后函数名变了**——`order.__name__` 已经是 `fn_inner`。本阶段知道即可，真实项目用 `@functools.wraps(func)` 保住原函数的名字和文档；
6. **以为装饰器每次调用都执行**——`@` 那一行在**函数定义时**执行一次（包一层），之后每次调用执行的只是内部函数。别在装饰器本体里写「每次调用都要做的事」，那些代码属于内部函数。

## 9. 课后小项目

**练习一：计数器闭包（必做）**

写 `make_counter()`：每次调用返回的函数，调用一次打印的数就加一（1、2、3……）。要求两个计数器互不干扰。就用到第 4 节的全部知识，五分钟写完的那种。

**练习二：计时装饰器**

写 `@timer`：装饰任意函数，调用时打印「函数名 耗时 x.xx 秒」。掐表用 `from time import time`，调用前后各取一次 `time()` 相减。拿它去量第 11 篇练习四的语料统计器跑多久。

**练习三：重试装饰器**

写 `@retry`：装饰一个「调 API」函数（用 `random.randint(1, 3)` 模拟返回结果，1 当成功），调用失败自动重试，最多 3 次，每次打印第几次尝试。内部函数里写 `for` 循环加 `try/except`——第 9 篇的异常处理在这里再上岗一次。

**练习四：给日记本装上外挂（综合收官）**

第 11 篇练习一的日记本，这次升级：写一个 `@log_action` 装饰器，每次执行写日记函数前，往 `app.log` 文件里追加一行「时间 + 执行了什么」。文件操作 + 装饰器 + 闭包，三篇的内容在一个程序里会师。
