第一个专题，说说 Manus。之前我在别处讲过它，这里重新整理一遍我现在的理解。

## 一波 N 折的经历

Manus 在 2025 年和 2026 年经历了一波不知道多少折：

- 2024 年，公司拒绝了字节跳动的收购
- 2025 年 3 月，发布 Manus 产品，迅速爆火，随后开放注册、开始收费，并迅速「润」到新加坡
- 2025 年 8 月，完成 9000 万美元的年化收入，大约 9 个月实现 ARR 破 1 亿美元，非常快
- 2026 年依然曲折：2025 年底宣布 Meta 以 20 亿美元收购，然后停止大陆服务，随即商务部启动审查，4 月决定禁止这笔收购，于是必须回购股份、与 Meta 运营切割，9 月宣布恢复独立运营，10 月又开始融资，融了 5 亿美元，目前目标估值大概 40 亿美元——是 Meta 收购价的两倍

你可以唱衰 Manus，但人家的估值还在不断翻倍。虽然估值不是现金，但它也很说明问题。

## 它做对了什么

下面讲我对 Manus 的理解和评价：先说它做对的，再说做错的。

**第一，把 Agent 定义成「交付结果」而不是「交付回答」**。别的产品给你一段话，Manus 给你一份做完的报告、一个已上线的网站，还能复述它每一步是怎么做的。这一点是之前所有 Agent 都做不到、之后所有 Agent 都必须做到的。在这件事上，Manus 定义了接下来几代 AI Agent 的范式，这是不可磨灭的贡献。

**第二，不训练自己的模型**。对一个创业公司而言，它没有能力训练模型，只能押注「模型会变得更强」，把功夫花在上下文工程上。联合创始人季逸超有个比喻：如果模型的进步是上涨的潮水，Manus 要做船，而不是做钉在海底的柱子——产品要随着模型变强而变好。这个选择让他们能按小时、而不是按周来发布改进。这个判断本身没有任何错。

但问题出在后面：创业公司该怎么理解自己和模型的关系？我觉得就该学 Manus——认真研究「模型变强会不会让你的产品彻底毁掉」，同时把跟风蹭流量的人挡在外面。

**第三，看准了付费的人是谁**。它瞄准的是愿意为时间付钱的专业人士，而不是长线流量，所以它用订阅制、上线第一天就收费，来筛出真正的付费用户。

## 上下文工程的四条经验

Manus 最关键的贡献，是它的上下文工程经验，一共四条：

**第一条最重要，关于 KV 缓存命中率**。要围绕 KV 缓存来设计 Agent 系统。Agent 每走一步，都要把之前的全部记录连同新结果重新交给模型，输入越积越长，而输出往往只有一行工具调用，输入输出比大概是 100 比 1。只要每次输入的开头保持不变，模型就能复用上一次算好的中间结果。速度和成本很大程度上取决于此——缓存命中率越高，整个 Agent 系统的成本就越低。

**第二条：把文件系统当成记忆**。上下文里只留路径，需要时再读回来。OpenClaw 用的就是这个模式，但 Manus 把它做到了极致——直接给 Agent 一台电脑、一个工作空间。

**第三条：用 Todo 来复述目标**。把目标放到上下文的末尾，防止 Agent 做着做着跑偏。

**第四条：保留出错的记录**。让模型看到自己犯过的错，接下来几次操作里就不会再犯。

这四条后来全部成了行业的通用知识，「按需加载」的思路还被 Agent Skills 写成了开放格式。这就是之前说过的：能写进博客的内容，很快就会开源化，然后人人都在用。这是 Manus 对整个行业不可磨灭的贡献。

## 它算错了什么

再说 Manus 判断错的地方。

**第一，模型公司自己做了 Agent**。Manus 当时没意识到这一点，他们可能以为大模型厂商看不上 Harness 这一层。事实不是这样，他们低估了大模型厂商跟进 Agent Harness 的速度。比如 2025 年 7 月，OpenAI 就把 Operator 和深度研究整合成了 ChatGPT Agent，当时已经能干很复杂的活；2026 年又有 Cowork 和 ChatGPT Work。

**第二，通用 Agent 并没有成为一个独立的产品形态**。它只是聊天产品里的一个模式，和各家的 Work 产品共用一个底座。它（连同 Genspark）都很难算一个已经完全站住的独立产品品类。

**第三，只做云端这条路线没坚持住**。后来它也推出了进用户浏览器、用用户电脑的产品。这说明「Agent 放在云端统管、不做本地执行」的最初判断有问题——确实有大量数据在用户本地和其他设备里，你总不能让用户事事都先传上来。

**第四，低估了地缘政治的影响**。迁新加坡、开曼控股收购这些操作，最后还是被叫停了——迁移注册地，改变不了研发所在地。

前三条其实是同一件事：Manus 低估了模型公司吞掉 Agent 这一层的速度。借用季逸超自己的比喻——潮水自己会开始造船了。

## 收购案的时间线与「洗澡式出海」

收购案被禁的过程本身也很坎坷。这期间出现一个说法叫「洗澡式出海」：在北京组建团队做研发、攒早期用户，然后把总部迁到新加坡、裁掉国内员工、清空国内账号，用开曼控股的公司以海外身份卖给 Meta——像洗澡一样，把整个中国背景全部洗掉。

但这条路走不通，因为研发地、数据所在地、团队来源都会被追溯，改注册地改不了这些事实。而且风险是双向的：2025 年 Benchmark 的投资引来了美国对华投资规则的审视，2026 年 Meta 收购又被中国叫停。「在中国起步、迁新加坡、卖给美国大公司」这条路，两头都被堵上了。对后来的中国创业公司来说，这些问题是你第一天就要开始规划的变量。

## Manus 2.0

Manus 2.0 是 2026 年 9 月发布的——在它脱离 Meta、恢复独立主体之后的新版本。新一代自研 Harness 在一项基准测试里比上一代少用 Token、少花时间，成本更低，同时还推出了直接使用用户电脑的 Manus Studio。

你可以说 Manus 这又倒回去模仿 OpenClaw 了——但不能说它在抄 OpenClaw，因为 OpenClaw 是它的「孙子」辈。与此同时云电脑依然在用，任务可以交给云端继续跑。这个结构和现在的 ChatGPT、Claude 产品一样：云端有 Harness、能跑代码，本地也有 Harness，一模一样。

最后还有独立的应用——一组个人代理，每个代理都有自己的邮箱、电话、数字钱包和电脑。它正好属于第六代 AI Agent 的品类，就是 Google、Meta 和 OpenAI 都在做的那种。

## 专题总结

关于 Manus 的总结：它证明了 Agent 作为产品类别是成立的，但没来得及证明 Agent 作为一家独立公司是成立的。

它开创了 Agent 这个产品，让原本人人质疑的 Agent 品类，成了现在行业的杀招。但它自己没办法证明，一家 Agent 公司能够完全独立运营——目前看来还不行。

2025 年 3 月的时候，大家会把这两件事混为一谈；到 2026 年，这两件事已经可以分开了。

它在产品和工程上的判断几乎全对，错就错在两个问题上：第一，Agent 这一层到底能不能独立存在；第二，主权风险的定价问题。

更一般地说，凡是能被描述、被协议化、被标准化的东西，很快都会变成公共知识。能留在你手里的只有三样：分发渠道、真实任务累积的数据、能承担风险的主体资格。这三样 Manus 之前一样也没有，目前看，可能只有数据有一定的积累。

但 Manus 作为先驱者获得了历史地位，历史记住了它的名字。这家公司未来的命运，我觉得还是前途未卜。
